**先看请求数，再看延迟。** 这个项目的成本与延迟都由对象存储请求驱动：

## 如何复现

```bash
./gradlew :yb-bench:benchPublic \
  -PYB_BENCH_PROFILE=ci -PYB_BENCH_OUT=bench/current.json
scripts/bench-compare.py --baseline bench/baseline-<profile>.json \
                         --current bench/current.json
```

用 `-PYB_S3_ENDPOINT` / `YB_S3_ACCESS_KEY` / `YB_S3_SECRET_KEY` 可以打真实桶；默认用进程内的 S3 兼容服务器，这样测的是 YangBase 本身而不是网络抖动。

## PR 门禁管什么

- **硬失败**：`requestsPerOp` / `bytesPerOp` / 存储足迹回退超过 5%。这些是确定性指标，回退就是真回退。
- **例外 —— 并发写入**：组提交的批次大小取决于线程调度，代码没变也会在机器之间飘（第一次 CI 就撞到 0.188 → 0.212）。所以它改用**不变式**门禁：平均每事务请求数必须 ≤ 1。
- **仅告警**：p50/p95/p99 延迟回退超过 5%（下限 200 µs 噪声地板）。共享 CI 机器撑不起延迟硬门禁，硬做只会让人把门禁关掉。
- **不在此页**：需要真实云后端的数字（OSS/COS/OBS/R2/B2 的延迟画像）。那些在 conformance 报告里，不在这里。
