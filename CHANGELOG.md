# Changelog

All notable changes to this project are documented here.

The format follows [Keep a Changelog 1.1.0](https://keepachangelog.com/en/1.1.0/), and the project
adheres to [Semantic Versioning](https://semver.org/). The version policy — what counts as MAJOR,
MINOR and PATCH, the weekly release train, and the freeze rule — is in
[docs/en/versioning.md](docs/en/versioning.md).

`Known issues` is a mandatory section in this project: a release without one is a release that is
pretending not to have any.

## [0.1.0] - 2026-10-30

First public release. Everything below has been exercised against a real MySQL client (MySQL
Connector/J 9.1), the project's embedded S3-compatible server, MinIO, and Alibaba Cloud OSS.

### Added

- **`ObjectStore` SPI** with capability probing (5 operations, 3 decorators, 3 backends) and a
  conformance suite whose result matrix is generated by CI rather than written by hand.
- **S3-compatible backend** with conditional writes, `Range`, paginated `LIST`, plus
  `--s3-provider` presets for AWS S3, MinIO, Alibaba Cloud OSS, Tencent COS, Huawei OBS,
  Cloudflare R2 and Backblaze B2. A preset declares a capability ceiling; the effective set is
  always `declared ∩ probed at startup`.
- **Alibaba Cloud OSS support** using OSS's own primitives: atomic create via
  `x-oss-forbid-overwrite`, three-level domain addressing. Verified against real OSS for both a
  single CN and a multi-CN + 3-node MS deployment.
- **LSM engine**: memtable, group-commit WAL, SST with `.idx`/`.dat` split, block compression
  (`-56.6%` on `.dat` over 20k rows), manifest pointer swap, crash recovery.
- **MVCC snapshot isolation**, cross-shard two-phase commit, row locks through the coordination
  service, `SELECT ... FOR UPDATE` with a pre-commit lock self-check.
- **Indexes**: ordered / hash / unique / composite secondary indexes, online index build
  (BUILDING → backfill → catch-up → ACTIVE), skip indexes (minmax / set / bloom / ngram),
  full-text search (`MATCH ... AGAINST`, `WITH PARSER ngram`, BM25 + WAND), partition pruning and
  composite-primary-key range pushdown.
- **`COUNT(*)` with zero data `GET`s** — exact, and asserted at `get_range == 0` in integration tests.
- **Partitioning** (`HASH` / `KEY` / `RANGE` / `LIST`); a partition is a write shard.
- **Time travel and recovery**: GC watermark, `AS OF TIMESTAMP`, PITR, backup/restore, recoverable
  `DROP TABLE`.
- **Online `ALTER TABLE`**: add column, drop trailing column, add/drop index, rename, `TRUNCATE` —
  all O(1) metadata, no data rewrite.
- **CDC change streams** reading the existing WAL directly, with persistable cursors.
- **Segmented auto-increment allocation**: no duplicates across restarts or nodes; 1000 allocations
  write the watermark object once.
- **Optimizer**: `ANALYZE TABLE` (reads only `.idx`, 0 `get_range`), histograms, HLL cardinality,
  cost model, `EXPLAIN`.
- **SQL surface**: aggregates, `GROUP BY`/`HAVING` with `ONLY_FULL_GROUP_BY` enforced, `JOIN`
  (inner/left/right/cross), `UNION`, `DISTINCT`, window functions, subqueries (correlated in
  predicate and scalar position), JSON function family, fixed-point `DECIMAL` arithmetic.
- **MySQL protocol**: handshake, `COM_QUERY`, prepared statements, server-side cursors,
  multi-statement, character sets; `information_schema` and the `SHOW` family; verified with a real
  JDBC driver end to end.
- **Metadata service** (Raft log and snapshots in object storage, cold start < 3s) and **three
  coordination modes** — `single`, `objectstore`, `ms` — sharing one consistency test suite.
- **Disk (NVMe) second-level cache**: after a CN restart, reading the same data issues 0 object-store
  requests.
- **Observability**: `/metrics`, `/healthz`, slow query log, object-storage audit log; scraping
  costs no object-store requests.
- **`yb-cli`**: `ls` / `shards` / `gc` / `recover-check` / `cost` / `backup` / `backups` /
  `restore` / `pitr` / `cdc` / `analyze-sql`, operating directly on object storage without a CN.
- **`commit_mode=async`**: acknowledges after the PUT is *issued*, with an ordered background
  upload pipeline, unbounded retry (no acknowledged write is ever dropped), bounded in-flight window
  (RPO ceiling = 64 batches), and metrics that state the window explicitly.
- **Batch delete** (`DeleteObjects`, 1000 keys per request) in the `ObjectStore` SPI: a bucket cleanup
  that used to cost `2N` requests (a `HEAD` plus a `DELETE` per key) now costs `ceil(N/1000)`.
  Alibaba Cloud OSS requires `Content-MD5` on that call and rejects it with a bare
  "Missing Some Required Arguments" otherwise, so the adapter computes it; verified against real OSS.
- Apache-2.0 license, CI (build + coverage gate + integration + real-OSS nightly), issue/PR
  templates, security policy, English README, bilingual docs (`docs/en`, `docs/zh`).
- **`docker compose up -d --wait` gets a queryable server in about a minute**: a multi-stage image
  (JDK build → JRE runtime, non-root, health check on the MySQL port) plus a compose file that
  brings up an S3-compatible object store. Compose is health-gated, so `--wait` returns only after
  the server really accepts MySQL connections; CI runs the same stack and queries it with a real
  MySQL client.

### Changed

- `version.txt` is the single source of truth for the version number; the release workflow refuses
  a tag that disagrees with it. Weekly release train introduced (see versioning policy).
- `--s3-provider` presets replace hand-copied endpoint/flag combinations; CLI and server share one
  resolver.
- Conditional-write failures are classified at the source by the precondition that was sent, instead
  of by the status code alone.

### Fixed

- **`DECIMAL` columns lost precision** in `+`, `-`, `*`, `%` — now fixed-point `BigDecimal`
  arithmetic, with tests.
- **A `COM_QUERY` containing only comments never produced a reply**, leaving the client hung for its
  full timeout. MySQL 8.4 clients send comment lines from `mysqldump` output verbatim, so this was
  reachable in practice; the server now answers with an empty OK packet.
- **`If-Match` mismatches on S3/OSS were reported as `PreconditionFailed` instead of a conflict**,
  so the manifest fencing branch could not catch them. Both `412` variants were indistinguishable
  before; they are now separated by the precondition we sent.
- **A Raft leader that stepped down did not fail its pending writes** — callers waited out the full
  commit budget and then received a misleading error, while the new leader's log overwrote the
  entry. `demoteLocked()` now fails unacknowledged writes immediately on all four demotion paths.
- **`SHOW VARIABLES LIKE 'commit_mode'` reported a stale session field**, so a `--commit-mode batch`
  instance claimed to be `sync`.
- **Three tests never ran**: expression-bodied `runBlocking { … }` test methods return a value, so
  JUnit 5 silently skipped them. They now run, and one of them guards the conditional-write
  classification above.
- Integration tests against a real backend now go through the same L1 retry layer that production
  uses; a single TCP connect timeout to a remote region no longer shows up as a false failure.
- Design document calibrated to the implementation in 12 places (SPI count, transport, `.idx`
  ratio, commit-mode levels, request-count definition, and others) instead of leaving intent and
  reality to diverge silently.

### Known issues

- **No authentication, permissions or TLS.** Any username and password are accepted; deploy on a
  trusted network only. Deliberately out of scope until the next fiscal year.
- **The default isolation level (`REPEATABLE READ` = snapshot isolation) does not prevent write
  skew.** InnoDB's next-key locking largely does. Applications relying on InnoDB locking semantics
  can see new anomalies after migrating.
- **Auto-increment values are not contiguous** (segmented allocation, same class of behaviour as
  `innodb_autoinc_lock_mode=2`).
- **Alibaba Cloud OSS has no ETag CAS**, so the manifest pointer switch is not atomic there; it
  requires the explicit `--i-accept-nonatomic-pointer-switch` downgrade, and the `objectstore`
  coordination mode cannot be used.
- **Writes to a non-owning CN are rejected rather than forwarded** — the error does not yet name
  the owner (#14).
- **Storage tiers / lifecycle rules are not implemented.**
